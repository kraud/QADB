# Reka UI Adoption Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace every native select, and the hand-built components Reka UI does better, without changing the app's look or behaviour.

**Architecture:** Pages keep using `app/components/ui/*` and the same props where possible; only those wrappers use Reka UI primitives. Styling stays in `app/assets/tokens.css`.

**Tech Stack:** Nuxt 4, Vue 3, `reka-ui` 2.x, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-26-reka-ui-design.md`

## Global Constraints

- Branch `generic-scenarios`; never merge to `main` or push.
- pnpm 11 (`/opt/homebrew/bin/pnpm`). The only new dependency is `reka-ui` `^2.11`.
- Same look (existing tokens and class names, light and dark, 960px and 720px), same copy, same behaviour except the gains listed in the spec.
- No Tailwind, no new features.
- No hydration warnings and no Reka console warnings.
- Controls are located by role and label; flow helpers contain no assertions.
- Existing end-to-end behaviour assertions are kept; only how a control is operated or queried may change.
- Never connect to a remote database; tests use their own ports, never `.localdb`, 8080 or 3000 (the user may be running the app).
- Every task ends with `pnpm typecheck`, `pnpm test`, `pnpm build` and `pnpm test:e2e` passing.

## Review Focus

1. A very long scenario or option name in a select: truncated in the trigger, wrapped or truncated in the list, no horizontal overflow at 390px (Task 1).
2. A list with 50 options near the bottom edge: stays inside the viewport and scrolls; the last option is reachable by keyboard (Task 1).
3. Escape with a list or popover open inside a dialog closes only that layer; a second Escape asks about unsaved changes as before (Tasks 2 and 4).
4. Nested dialogs: closing the top one returns focus to the one beneath, and closing the last returns it to the button that opened it (Task 2).
5. Several toasts at once: all readable, none blocks clicks on the page (Task 4).
